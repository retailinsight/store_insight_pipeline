OSA Availability
Fires when a store-department's on-shelf availability is materially below the chain average, drops sharply week-on-week, or contains items that have failed persistently across multiple weeks.
Detection Methods
WOW Week-on-Week
Fires when OSA falls more than min_wow_drop percentage points compared to the previous week, and lost sales value this week exceeds min_lost_sales_value.
BaselineSame store-department OSA last week Thresholdsmin_wow_drop · min_lost_sales_value
VS_CHAIN vs Chain Average
Fires when the store OSA is more than min_chain_gap percentage points below the chain-wide average for the same department this week, and lost sales value exceeds min_lost_sales_value.
BaselineChain-wide average OSA this week Thresholdsmin_chain_gap · min_lost_sales_value
REPEAT Persistent Failure
Fires when one or more items in a store-department have triggered an availability alert in at least min_alert_weeks of the rolling lookback window (default 10 weeks). An alert week = weekly OSA < (1 − min_osa_drop) AND weekly LSV > min_weekly_lsv.
BaselineItem OSA over rolling 10-week lookback Thresholdsmin_alert_weeks · min_osa_drop · min_weekly_lsv

Investigation Skill
Purpose
Guide the investigation of an OSA (on-shelf availability) alert for a store-department. Generates card content that is specific, commercially grounded, and actionable for a store manager.
Key Signal Fields
FieldDescription
this_week_lsvTotal lost sales value for the department this week
this_week_osaStore-department OSA % this week
last_week_osaStore-department OSA % last week (WOW trigger)

Narrative Construction
  • Lead with strongest trigger: REPEAT > VS_CHAIN > WOW
  • Open explanation with the £ lost sales figure and OSA context
  • Use subclass_contributors and subclass_changes to name top 1–3 products
  • Use worst_day from DOW facts to anchor recommended action timing
  • For REPEAT: focus recommended action on root cause (parameters, lead times, capacity)
  • Cost if Not Fixed: "If this continues at the same rate, the store could lose approximately £X in the next N weeks."
  • Do not reference trigger type names (WOW, VS_CHAIN, REPEAT) in card — use plain English
  • Do not fabricate product names or £ figures not present in signal data
Compliance Compliance
Fires when a store's rate of alerts dismissed without genuine investigation (tick-and-flick) has risen week-on-week and exceeds the chain average — indicating poor compliance with the alerting process.
Detection Methods
TICK_AND_FLICK Rapid Dismissal
Fires when all three conditions hold: tick-and-flick rate rose ≥ min_wow_increase pp week-on-week; store rate exceeds chain average by ≥ min_chain_outperform pp; store worked ≥ min_alerts_worked alerts this week.
BaselineChain-wide tick-and-flick rate this week Thresholdsmin_wow_increase · min_chain_outperform · min_alerts_worked

TICK_AND_FLICK_FLAGBoolean — true if the alert was dismissed without genuine investigation
ALERT_TYPE_NAMEAlert category — used in the department breakdown gatherer to identify which types are being dismissed
Facts Gathered
tick_and_flick_breakdown
tf_by_alert_type
Breakdown of tick-and-flick dismissals by alert type for each flagged store — shows which alert categories are being dismissed most carelessly (worked, tf_count, tf_rate per type).
Investigation Skill
Purpose
Guide the investigation of a COMPLIANCE alert triggered by the tick-and-flick detector. Generates card content that is specific and actionable for a store manager or area manager.
Key Signal Fields
FieldDescription
this_week_tf_rate% of alerts worked this week that were tick-and-flick

Narrative Construction

  • State week-on-week change and gap above chain average
  • List worst 1–3 alert types from tf_by_alert_type
  • Where rate is rising, add urgency — suggest coaching session with store manager
  • Cost if Not Fixed: qualitative only — "Unresolved alerts mean availability issues go unaddressed, increasing the risk of lost sales." Do not fabricate a £ figure
  • Do not reference TICK_AND_FLICK as a technical term — use plain English
Markdown Override Markdown
Fires when a store is overriding the markdown algorithm at a rate materially above the chain average or that has risen sharply week-on-week — indicating poor adherence to pricing guidance.
Detection Methods
VS_CHAIN vs Chain Average
Fires when the store override rate exceeds the chain average by more than min_override_chain_gap pp, and the store processed at least min_total_markdowns markdowns this week.
BaselineChain-wide override rate this week Thresholdsmin_override_chain_gap · min_total_markdowns
WOW Week-on-Week
Fires when the override rate has risen by more than min_override_wow_increase pp compared to last week, and the store processed at least min_total_markdowns markdowns this week.
BaselineSame store override rate last week Thresholdsmin_override_wow_increase · min_total_markdowns

ORIGINAL_PRICEFull retail price before markdown — used in waste value calculations
MARKDOWN_PERCENTAGEDepth of the markdown applied — averaged for context in SKU signals
QTY_MARKDOWNUnits put through the markdown process — denominator for waste rate metric

override_dept_breakdown
Top-N departments by override count and override rate this week for each flagged store. Each entry contains: dept, total_markdowns, overrides, override_rate_pct.
Investigation Skill
Purpose
Guide the investigation of a MARKDOWN_OVERRIDE alert. A store is overriding the markdown algorithm at a rate that is either significantly above the chain average (VS_CHAIN) or has risen sharply week-on-week (WOW). Overriding means staff manually changed the recommended price — typically reducing it less than suggested, causing items to sit on the shelf longer and increasing waste risk.
Key Signal Fields
FieldDescription
this_week_override_rate% of markdowns overridden this week
chain_override_rateChain-wide override rate this week
above_chain_pppp above chain (VS_CHAIN trigger only)
last_week_override_rate% overridden last week (WOW trigger only)
wow_change_pppp change week-on-week (WOW trigger only)
this_week_total_markdownsTotal markdown events this week
this_week_overridesNumber of overrides this week
Narrative Construction
  • State raw numbers: "{overrides} of {total_markdowns} markdowns were overridden ({rate}%)"
  • VS_CHAIN: "Chain average is {chain_rate}% — this store is {above_chain_pp}pp above"
  • WOW: "Last week the rate was {last_week_rate}% — up {wow_change_pp}pp"
  • Name top 1–2 departments from override_dept_breakdown if available
  • Cost if Not Fixed: qualitative — overridden items are at increased risk of reaching end-of-life unsold. Do not project a £ cost
  • Frame as guidance and training, not accusation — do not name individual staff
Markdown Sell-Through Markdown
Fires when a store's markdown sell-through rate (proportion of marked-down items actually bought by customers) is materially below the chain average or has dropped sharply week-on-week — indicating the markdown process is not working.
Detection Methods
VS_CHAIN vs Chain Average
Sell-through rate = SUM(MARKDOWN_QUANTITY sold) / SUM(MARKDOWN_QUANTITY + WASTE_QUANTITY). Fires when the store rate is more than min_sellthrough_chain_gap pp below the chain average, and the store processed at least min_markdown_qty markdown units this week.
BaselineChain-wide sell-through rate this week Thresholdsmin_sellthrough_chain_gap · min_markdown_qty
WOW Week-on-Week
Fires when the sell-through rate has fallen by more than min_sellthrough_wow_drop pp compared to last week, and the store had at least min_markdown_qty markdown units this week.
BaselineSame store sell-through rate last week Thresholdsmin_sellthrough_wow_drop · min_markdown_qty
Data Sources

ITEM_IDItem identifier — used in department breakdown join
DATEDate of the markdown sale — used to window into weeks
MARKDOWN_QUANTITYUnits sold through the markdown programme — numerator of sell-through rate
MARKDOWN_VALUE£ revenue from markdown sales this period
SOURCE_WMD_WASTAGE
STORE_IDStore identifier
ITEM_IDItem identifier — used in department breakdown join
DATEDate of the waste event — used to window into weeks
WASTE_QUANTITYUnits wasted — added to MARKDOWN_QUANTITY for the sell-through denominator
ORIGINAL_PRICEFull retail price — used to compute waste value
SOURCE_WMD_STORE_HIERARCHY
STORE_IDStore identifier — join key
STORE_NAMEHuman-readable store name — surfaced as SITE_NAME
Facts Gathered
markdown_sellthrough_dept_breakdown
sellthrough_dept_breakdown
Top-N departments ranked by lowest sell-through rate this week. Each entry contains: dept, requested_qty, sold_qty, sellthrough_rate_pct, markdown_value. Requires markdown_sales, markdown_log, and item_hierarchy DataFrames.
Investigation Skill
Purpose
Guide the investigation of a MARKDOWN_SELLTHROUGH alert. A store's sell-through rate is below the chain average or has dropped sharply week-on-week. A low sell-through means items are being reduced in price but customers are not buying them — ultimately leading to waste.
Key Signal Fields

this_week_markdown_value£ value of markdown sales this week
Narrative Construction
  • State: "Of {markdown_qty} markdown units, {rate}% were sold, generating £{value} in markdown revenue"
  • VS_CHAIN: name chain average and gap; WOW: name last week rate and drop
  • Name worst 1–2 departments from sellthrough_dept_breakdown
  • Root cause prompt: markdown too shallow, product placement, or product-market fit
  • Cost if Not Fixed: frame as waste exposure ("items not sold at markdown will progress to waste"), not lost revenue. Do not project a precise £ waste figure
Markdown SKU Markdown
SKU-level alert. Fires when a specific item at a specific store has been marked down repeatedly across recent weeks (chronic surplus), or is being overridden at a disproportionately high rate (persistent staff resistance to pricing guidance for that SKU).
Detection Methods
REPEAT_REQUEST Chronic Surplus
Fires when the item has been marked down on at least min_markdown_weeks distinct weeks AND has at least min_markdown_requests total requests within the lookback_weeks rolling window ending this week.
BaselineDistinct weeks item was marked down in the rolling window Thresholdslookback_weeks · min_markdown_weeks · min_markdown_requests
EXCESSIVE_OVERRIDE SKU Override Rate
Fires when the item has an override rate ≥ min_sku_override_rate (e.g. 50%) AND at least min_sku_requests total markdown requests within the lookback_weeks rolling window.
BaselineOverride rate for this item at this store over the rolling window Thresholdslookback_weeks · min_sku_override_rate · min_sku_requests

ITEM_IDInternal numeric item identifier (LongType) — the per-SKU grouping key
LOCAL_DATEDate of the markdown event — truncated to WEEK_START for week counting
IS_OVERRIDDENBoolean — whether this request was overridden by staff
MARKDOWN_PERCENTAGEDepth of the markdown — averaged across the window for context
SOURCE_WMD_ITEM_HIERARCHY
VMECODE → ITEM_IDInternal numeric item ID (LongType) — join key to markdown log. Note: table has ~109M rows from multi-snapshot loading; deduplicate by VMECODE using latest FILE_TIMESTAMP
ITEM_DESCRIPTIONHuman-readable item name — surfaced in the signal for the card title
DEPARTMENTDepartment the item belongs to — used for grouping context

STORE_IDStore identifier — join key
STORE_NAMEHuman-readable store name — surfaced as SITE_NAME
Facts Gathered

sku_markdown_history
Week-by-week markdown request and override history for each flagged store-SKU combination. Ordered oldest to newest — each entry contains week_start, request_count, override_count, avg_markdown_pct. Used to surface trend in the narrative.
Investigation Skill
Purpose
Guide the investigation of a MARKDOWN_SKU alert — a SKU-level alert about a single item. Unlike store-level markdown alerts, this warrants a targeted SKU-level conversation. REPEAT_REQUEST = ordering/demand problem. EXCESSIVE_OVERRIDE = compliance/training problem. Recommended actions differ.
Key Signal Fields
FieldDescription
item_idInternal item identifier
item_descriptionHuman-readable item name
departmentDepartment this item belongs to
markdown_request_countTotal markdown requests for this item in the window
override_countNumber of requests that were overridden (EXCESSIVE_OVERRIDE only)
lookback_weeksRolling window length in weeks
avg_markdown_pctAverage markdown depth % over the window
Narrative Construction
  • REPEAT_REQUEST title: "[item] marked down {count} times in {weeks} weeks"
  • EXCESSIVE_OVERRIDE title: "[item] overridden {overrides} of {total} markdown requests in {weeks} weeks"
  • If both triggers merged: lead with EXCESSIVE_OVERRIDE, add repeat context
  • Use sku_markdown_history to describe trend (worsening / stable / improving)
  • REPEAT_REQUEST action: review ordering and ranging, consider whether item suits this store's customer profile
  • EXCESSIVE_OVERRIDE action: discuss pricing guidance with store manager; escalate to buying team if algorithm recommendation is consistently wrong
  • Do not project a £ cost — SKU-level waste projections require volume data not in this signal
Waste Waste
Fires when a store's waste rate (units wasted per unit put through the markdown process) is materially above the chain average or has risen sharply week-on-week — indicating the markdown process is not recovering stock effectively.
Detection Methods
VS_CHAIN vs Chain Average
Waste rate = WASTE_QTY / QTY_MARKDOWN. Fires when the store waste rate exceeds the chain average by more than min_stb_chain_gap pp, and the store wasted at least min_waste_qty units this week. Note: FINAL_PRICE is always NULL in source data — not used.
BaselineChain-wide waste rate (WASTE_QTY / QTY_MARKDOWN) this week Thresholdsmin_stb_chain_gap · min_waste_qty
WOW Week-on-Week
Fires when the waste rate has risen by more than min_stb_wow_increase pp compared to last week, and the store wasted at least min_waste_qty units this week.
BaselineSame store waste rate last week Thresholdsmin_stb_wow_increase · min_waste_qty
Data Sources
SOURCE_WMD_WASTAGE
STORE_IDStore identifier
ITEM_IDItem identifier — used in department breakdown join
DATEDate of the waste event — used to window into weeks
WASTE_QUANTITYUnits wasted — numerator of waste rate (WASTE_QTY / QTY_MARKDOWN)
ORIGINAL_PRICEFull retail price — multiplied by WASTE_QUANTITY to compute waste value (£)
WASTE_REASONReason for waste (AFTER BEST BEFORE DATE, TOO GOOD TO GO, OUT OF DATE, DAMAGED) — descriptive context, not used in detection logic
SOURCE_WMD_MARKDOWN_LOG_CONVERTED (denominator)
STORE_IDStore identifier — join key for waste rate denominator
LOCAL_DATEDate — used to window the denominator into the same week
QTY_MARKDOWNUnits put through the markdown process — denominator of waste rate metric

STORE_IDStore identifier — join key
STORE_NAMEHuman-readable store name — surfaced as SITE_NAME
Facts Gathered
waste_dept_breakdown
waste_dept_breakdown
Top-N departments by waste quantity and waste rate (WASTE_QTY / QTY_MARKDOWN) this week for each flagged store. Each entry contains: dept, waste_qty, stb_qty, stb_rate_pct, waste_value.
Investigation Skill
Purpose
Guide the investigation of a WASTE alert. A store's waste rate is above chain average or rising week-on-week. Waste rate = WASTE_QTY / QTY_MARKDOWN — normalised for activity so a high rate vs chain indicates the markdown process is not recovering stock effectively.
Key Signal Fields
FieldDescription
this_week_stb_rateWaste rate % this week (WASTE_QTY / QTY_MARKDOWN)
chain_stb_rateChain-wide waste rate this week
above_chain_pppp above chain (VS_CHAIN trigger only)
last_week_stb_rateWaste rate last week (WOW trigger only)
wow_change_pppp change week-on-week (WOW trigger only)
this_week_waste_qtyTotal units wasted this week
this_week_waste_value£ value of all waste this week (at original price)
Narrative Construction
  • VS_CHAIN: "Chain average waste rate is {chain_rate}% — this store is {above_chain_pp}pp above"
  • WOW: "Last week the rate was {last_week_rate}% — up {wow_change_pp}pp"
  • Name top 1–2 departments from waste_dept_breakdown by STB quantity
  • Root cause prompt: items missed by markdown process, over-ordering, or staff binning before markdown applied
  • Cost if Not Fixed: "Items worth approximately £{this_week_waste_value} per week are being discarded that could have generated revenue through markdowns." (Not all waste is recoverable — markdown revenue typically 30–70% of original price)
  • Do not conflate total waste with straight-to-bin waste — some waste (damaged items) is unavoidable
